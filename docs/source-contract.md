# TitleVault 来源约定

此服务管理保管来源领取、控制声明关联及原件资料交付。它不办理转让或放货，只回答：某份原件在交接前后由谁控制，资料是否足以支持当前齐备。

## 目录与原文

当前业务使用一个选定来源上下文。目录请求为 `GET /custodian/A`，返回 `custodian` 与 `originals`。每个目录成员以 `id`、`href` 提供来源身份与原文位置；可选 `relations` 明确给出该成员的关联资料位置，省略时按 `/custodian/<context>/relations/<id>` 取得。原文中的 `document` 和 `custodian` 必须与目录一致，原文位置也必须落在该保管方的 `/custodian/<context>/` 之下；否则不能作为该保管方的授权来源使用。

```json
{
  "document": "D1",
  "custodian": "A",
  "bill": "BL100",
  "original": "ORIG1",
  "holder": "出口公司",
  "state": "active"
}
```

字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。`state` 只识别 `active` 与 `surrendered`；其他状态要求保管员复核，不能默认为可用。

## 关联资料：背书链与交还凭证

关联资料与目录**不承诺同时发布**。同一保管方可在 `/custodian/A/relations/D1` 发布：

```json
{
  "endorsements": [
    { "id": "E2", "previous": "ORIG1", "next": "ORIG2", "from": "A", "to": "B", "href": "/custodian/B/ORIG2" }
  ],
  "surrenders": [
    { "id": "S1", "original": "ORIG2", "from": "B", "to": "C" }
  ],
  "nextOriginal": "/custodian/B/ORIG2"
}
```

- `endorsements` 是有向交接声明：`previous` 是交出方控制的原件，`next` 是受让方的原件，`from`/`to` 是参与方。可用 `href` 直接给出新原件位置；否则从 `nextOriginal` 解析。`nextOriginal` 可为字符串、`{original, href}`、数组或 `{ "ORIG2": "/…" }` 映射。
- `surrenders` 是交还声明，只表示该原件已交还，**不表示**后继存在可用的当前原件。
- `nextOriginal` 只提供位置，不构成控制声明。

一条来源的背书声明不能单独替受让方确认交接：只有该声明指向的新原件也能在**其声明的保管方路径**下取得，且内容中的 `original`、`custodian`、`bill` 与声明和提单一致时，才形成相互支持的依据。多段交接逐段核对；任何中间原件未取得时结论为 `not-arrived`，不以交出方的旧原件补位。

同一链中每个中间原件都必须能逐段核对；任一 `from`/`to` 与相邻段不衔接、同一原件出现多个不同的 `next`、交还声明与新的背书并存、链中出现环，或声明集合中存在与本链不相连的孤立交接，均视为争议，交保管员裁定，不能按最后抓取的一页决定权属。

## 访问结果的含义

HTTP 访问结果只说明本次可见权限，不说明单证业务状态：

| 结果 | 含义 |
| --- | --- |
| 200 | 本次可见；仍须核对内容与上下文 |
| 401 / 403 | 访问被拒，不能解释为已交还或已撤销 |
| 404 / 410 | 当前位置未发布，不能解释为已交还 |
| 429 / 5xx / 超时 | 暂时不可用，保留历史副本并稍后核对 |
| 越出授权保管方路径 | 不能作为该保管方授权来源使用 |

每次领取都记录可见权限、控制声明、原件摘要与交接依据。已合法取得的原文不因入口失效而删除；收件结论可以随观察更新，历史原文仍按摘要可复查。

## 收件结论

单条资料的可能结论：

| 状态 | 含义 | 是否计入当前齐备 |
| --- | --- | --- |
| `accepted` | 链与当前受控原件相互支持 | 是 |
| `not-arrived` | 交接声明已见，指向的新原件尚未出现或当前不可取得 | 否 |
| `unverified` | 缺少关联资料，或链未声明交接，交接尚未证实 | 否 |
| `surrendered` | 交还声明或状态已见，原件不列当前 | 否 |
| `historical` | 目录不再列出，保留已合法取得的历史副本 | 否 |
| `conflict` | 分叉、缺环、交还与背书并存或身份不一致 | 否 |
| `outside` | 不属于本次所选保管来源 | 否 |
| `error` | 来源可见但资料无法解释，或目录入口不可取得 | 否 |

只有全部单条资料均为 `accepted` 时，本次资料包才标记 `complete: true`。每个非完成结果都带有 `nextCustodian`，指明下一步应向哪个已授权保管来源补资料。

## 原文和收件存储

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策，并单独记录每次观察的可见权限与交接依据。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；只绑定回环地址，不连接真实监管、银行或合作方。`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。
